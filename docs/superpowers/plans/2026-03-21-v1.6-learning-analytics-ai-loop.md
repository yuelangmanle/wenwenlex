# 文文Lex v1.6 学习统计可视化与 AI 计划闭环增强 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把学习数据沉淀、可视化回看、AI 计划长期摘要输入和计划效果回看做成第一版正式闭环，并完成数据库迁移、备份升级、页面入口和云端发版准备。

**Architecture:** 保留当前四大主导航和 `AI 计划中心` 独立路由，不新增账号、服务器或新的底部 Tab。实现上先把“统计快照 + 长期摘要 + 计划效果”接入现有 `AiMemorySummary` 和 Room 持久化，再补 `feature/analytics` 的 HTML 看板页，最后把首页 / 我的页 / AI 计划中心入口接通，并完成备份 `v5`、测试和发版文档同步。

**Tech Stack:** Kotlin, Jetpack Compose, Android WebView via `AndroidView`, Room, DataStore, kotlinx.coroutines, JUnit4, Android instrumented tests, GitHub Actions.

```kotlin
class PlanEffectEvaluator {
    fun evaluate(
        currentPlan: PlanHistoryEntry,
        events: List<StudyEvent>,
    ): PlanEffectSnapshot {
        val beforeWindow = events.filter { it.happenedAt.isBefore(currentPlan.generatedAt) }.takeLast(40)
        val afterWindow = events.filter { !it.happenedAt.isBefore(currentPlan.generatedAt) }.take(40)
        return PlanEffectSnapshot(
            planVersionId = currentPlan.id,
            label = currentPlan.summary,
            beforeCorrectRate = beforeWindow.correctRate(),
            afterCorrectRate = afterWindow.correctRate(),
            outcomeSummary = summarizeWindowDelta(beforeWindow, afterWindow),
        )
    }
}
```

## 风险清单

- WebView + HTML 渲染如果引入过重脚本，会增加调试成本；首版必须坚持静态模板、少脚本、无联网依赖。
- 统计快照字段如果设计过大，`learner_profiles` 的 JSON 列可能膨胀过快；首版只保留 AI 连续性和页面展示真正需要的字段。
- 计划效果评估很容易“看起来很聪明但实际上不稳定”；首版只做规则化摘要，不做复杂推断。
- 备份 `v5` 一旦字段遗漏，会直接影响长期使用者升级；必须把旧版本兼容回归放进任务主线，而不是收尾时顺手补。
