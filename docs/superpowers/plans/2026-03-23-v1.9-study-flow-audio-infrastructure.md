# 文文Lex v1.9 学习流与发音基础设施 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use @superpowers:subagent-driven-development (recommended) or @superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把文文Lex 当前“首页像有计划、学习页却整本乱刷”的状态升级为可执行的三队列学习系统，并同步补齐发音来源、缓存管理、云端 TTS、语音包下载恢复这些基础体验短板。

**Architecture:** 保持现有首页、学习页、详情页、发音设置页的主结构不推倒重来，在此基础上新增“学习模式路由 + 队列规划器 + 分组过关状态机 + 音频任务中心”四条主干。学习流和发音基础设施共用同一套状态模型与后台任务框架，但实现上拆成独立文件，避免把学习逻辑和音频逻辑继续塞进少数大文件里。

**Tech Stack:** Kotlin, Jetpack Compose, Room, DataStore, WorkManager, Robolectric unit tests, AndroidX Test, GitHub Actions.

---

## Scope Check

这份 spec 同时覆盖学习流和发音系统两块，但两者都落在同一批页面与同一次发版里，而且学习页的“播放发音 / 切换来源 / 后台预缓存”与学习模式本身强耦合，所以这里不拆成两份计划。实施上仍拆成 3 个波次：

- Wave 1：学习流闭环
- Wave 2：发音可解释与缓存治理
- Wave 3：云端 TTS 与语音包下载收口

每个波次都必须独立可运行、可测试、可验收。
