# 文文Lex v1.2 发音与朗读模块设计文档

## 1. 背景

文文Lex `1.1` 已经具备：

- 真实内置词库
- `.xlsx` 词书导入
- 多 API 管理
- AI 音标补全
- 本地优先的学习闭环

但“发音”能力仍然停留在轻量占位状态：

- 词条模型只有单个 `pronunciationUrl`
- 没有真实的音频缓存层
- 没有统一的发音来源调度
- 没有离线朗读能力
- 没有语音包下载与挂载能力
- 没有把播放行为纳入长期学习分析

这会直接影响两个核心体验：

1. 单词详情和学习页无法稳定提供“标准单词发音”
2. AI 讲解、例句、整段解释无法在本地连续朗读

`v1.2` 的目标是补齐这一层，让文文Lex从“能背单词”升级到“能稳定听、能离线读、能把发音行为纳入学习分析”。

## 2. 版本目标

### 2.1 目标

- 为单词发音建立统一的来源调度链路
- 接入网络词典音频与本地缓存
- 接入可下载的离线 TTS 语音包
- 保留 Android 系统 `TextToSpeech` 作为兜底
- 支持英式 / 美式口音偏好和显式播放
- 支持语音包一键下载、校验、安装、挂载和删除
- 支持例句、AI 讲解和长文本朗读
- 将播放来源、失败原因和重播行为纳入学习事件，供 AI 后续分析

### 2.2 非目标

- 不在 `v1.2` 引入账号系统或云端同步
- 不自建音频或 TTS 服务端
- 不把大模型或大体积语音模型直接塞进主 APK
- 不在第一版实现商业词典平台级密钥托管
- 不在第一版实现复杂音频波形编辑、逐词对齐或跟读评分

## 3. 设计原则

- **词典音频优先**：标准单词发音优先来自词典音频，而不是 TTS 伪装
- **离线能力可选增强**：主包保持轻量，离线语音能力通过后装语音包提供
- **本地优先**：缓存、语音包、播放日志都必须本地落盘
- **显式降级**：不同来源必须能区分，不允许“静默换源”让用户误以为精度一致
- **可维护扩展**：后续替换词典源或新增语音包不应冲击页面层
- **连续性依赖结构化摘要**：长期 AI 分析使用本地结构化事件与摘要，不依赖无限增长的上下文

## 4. 方案选型结论

本次采用用户确认的 `B` 方案：

- 单词发音：
  `本地缓存词典音频 > 在线词典音频 > 已下载离线 TTS 语音包 > 系统 TTS`
- 句子 / 例句 / AI 讲解朗读：
  `已下载离线 TTS 语音包 > 系统 TTS`

不采用以下路线：

- 不采用“只做本地 TTS”的简化路线，因为无法稳定承担标准单词发音
- 不采用“只做网络词典音频”的路线，因为句子和 AI 讲解仍会缺少离线能力
- 不采用“主包直接内置大语音模型”的路线，因为包体、安装和迭代成本过高

## 5. 模块拆分

### 5.1 PronunciationOrchestrator

统一对外暴露“播放这个单词”或“朗读这段文本”的入口。

它负责：

- 选择当前播放策略
- 根据用户口音偏好决定优先级
- 串联缓存、网络词典、离线 TTS、系统 TTS
- 把播放来源、耗时、失败原因写回 telemetry

页面层只调用它，不直接访问词典源或 TTS 引擎。

### 5.2 DictionaryAudioRepository

负责单词词典音频资源。

职责：

- 按词和口音查找远端音频
- 下载音频到本地缓存
- 维护缓存状态和元数据
- 对失败结果做冷却，避免反复请求无音频词条

### 5.3 OfflineVoicePackRepository

负责语音包元数据与安装状态。

职责：

- 拉取语音包清单
- 发起下载
- 校验 `sha256`
- 解压和安装到应用私有目录
- 激活、切换、删除语音包

### 5.4 OfflineTtsEngine

负责加载已安装语音包并执行本地合成。

第一版按 `sherpa-onnx` 路线设计，模型以后作为后装资产提供，不进主包。

### 5.5 SystemTtsEngine

负责系统 `TextToSpeech` 初始化、语音选择和兜底播放。

它不是标准单词发音的首选来源，但必须作为最后兜底，防止整个发音链路失效。

### 5.6 PlaybackTelemetryRecorder

负责把播放行为写入学习事件，供 AI 做后续分析。

记录内容包括：

- 来源类型
- 口音
- 是否重播
- 是否失败
- 耗时
- 当前所处页面 / 学习会话

## 6. 数据模型与存储设计

`v1.2` 将数据库从 `v2` 升级到 `v3`。

### 6.1 兼容原则

- 保留 `Word.pronunciationUrl` 作为兼容字段
- 原有单词、学习、音标和词书数据全部保留
- 新增发音资源表与语音包表，不破坏旧数据结构

### 6.2 word_audio_assets

新增表 `word_audio_assets`，按“单词 + 口音 + 来源”维护可播放音频资源。

字段：

- `id`
- `wordId`
- `accent`：`uk | us | auto`
- `sourceType`：`dictionary_remote | dictionary_cache | offline_tts | system_tts`
- `remoteUrl`
- `localPath`
- `mimeType`
- `checksum`
- `status`：`empty | ready | failed | stale`
- `fetchedAt`
- `lastPlayedAt`
- `lastError`
- `failureCount`

用途：

- 支撑词典音频缓存
- 支撑远端失败冷却
- 支撑页面显示“当前使用了什么来源”

### 6.3 voice_packs

新增表 `voice_packs`。

字段：

- `id`
- `name`
- `locale`
- `accent`
- `engineType`
- `version`
- `downloadUrl`
- `manifestUrl`
- `installDir`
- `archiveChecksum`
- `installedSizeBytes`
- `status`：`not_installed | downloading | verifying | installing | ready | broken`
- `isActive`
- `createdAt`
- `updatedAt`

用途：

- 记录可下载与已安装语音包
- 管理当前激活语音包
- 支撑设置页状态展示

### 6.4 DataStore 设置项

新增设置项：

- `preferredAccent`
- `pronunciationMode`
- `allowCellularDownload`
- `autoCacheWordAudio`
- `audioCacheLimitMb`
- `activeVoicePackId`
- `fallbackToSystemTts`
- `preferOfflineForLongText`

### 6.5 学习事件接入

第一版不单独增加重量级日志表，而是扩展现有学习事件写入内容：

- `play_source`
- `play_accent`
- `play_success`
- `play_error`
- `play_repeat_count`
- `play_context`

理由：

- 足够支持 AI 分析
- 不额外增加复杂的查询面
- 后续如果事件量太大，再做汇总表

## 7. 下载、安装与挂载设计

### 7.1 主体流程

语音包使用 GitHub Release 资产托管。

主流程：

1. 打开“发音与朗读设置”页
2. 拉取 `voice-pack-manifest.json`
3. 展示可下载语音包列表
4. 用户点击下载
5. `WorkManager` 前台任务开始下载
6. 下载完成后校验 `sha256`
7. 解压到应用私有目录
8. 写入 `voice_packs`
9. 用户设为默认后，`OfflineTtsEngine` 按目录加载

### 7.2 目录规划

- 词典音频缓存：
  `files/audio-cache/words/<wordId>/<accent>.mp3`
- 语音包安装目录：
  `files/voice-packs/<packId>/`
- 临时下载目录：
  `cache/voice-pack-downloads/`

### 7.3 挂载定义

本项目中的“挂载”不指系统层 `mount`，而是：

- 下载归档
- 校验完整性
- 解压到私有目录
- 将安装目录写入数据库
- 播放时按该目录加载模型和资源

### 7.4 安全要求

- 每个语音包都必须校验 `sha256`
- 校验失败立即删除损坏归档
- 安装中断时保留中间状态，允许重新下载
- 不允许从任意用户输入 URL 直接静默执行模型加载

## 8. 播放链路设计

### 8.1 单词播放

以用户偏好口音为基线：

1. 查询本地缓存词典音频
2. 命中则直接播放
3. 未命中则查网络词典音频
4. 查到后立即播放，并异步写入本地缓存
5. 查不到或网络失败，则尝试离线语音包 TTS
6. 离线 TTS 不可用，则回退到系统 TTS

### 8.2 长文本朗读

1. 优先使用已激活离线语音包
2. 合成前按句切分，避免一次性文本过长
3. 语音包加载失败则回退系统 TTS

### 8.3 英式 / 美式策略

- 单词层面优先保持真实词典口音区分
- 如果词典只有一套音频，则允许用该套播放并标注来源
- 如果离线语音包只支持一种英语音色，不伪装成“真实双词典标准音”

## 9. UI 与交互设计

### 9.1 单词详情页

新增：

- 英式播放按钮
- 美式播放按钮
- 当前来源提示
- 预缓存入口

展示文案必须能区分：

- 已缓存词典音频
- 在线词典音频
- 离线朗读
- 系统朗读

### 9.2 学习页

- 保留一个主播放按钮
- 默认按偏好口音播放
- 长按可切换英 / 美
- 如果走了降级来源，显示轻提示，不强打断学习流程

### 9.3 发音与朗读设置页

新增设置页或在 AI 设置中增加独立模块，包含：

- 发音来源策略
- 默认口音
- 词典音频缓存大小
- 清空缓存
- 语音包列表
- 下载 / 删除 / 设为默认
- 仅 Wi-Fi 下载
- 测试朗读

## 10. AI 与长期连续性设计

本模块不是单纯给出声音，还要把“听”的行为纳入学习反馈。

### 10.1 需要采集的数据

- 哪些词被频繁重播
- 用户更偏向英音还是美音
- 哪些易混词组的播放频率显著更高
- 用户在学习哪个阶段更依赖发音
- 例句和 AI 讲解朗读的触发频率
- 哪些播放失败来源最常见

### 10.2 AI 输入原则

不把全部历史明细原封不动丢给 AI，而是先在本地生成结构化摘要：

- 最近 7 天播放摘要
- 最近 30 天发音依赖统计
- 高频重播词组
- 易混词听辨失败样本
- 当前活跃词书的发音使用习惯

### 10.3 AI 可输出的建议

- 是否更适合优先展示英式还是美式
- 哪些易混词需要加入“听辨练习”
- 哪些词只是拼写记住了但发音不稳
- 是否应在学习流程里增加更多“先听后看”或“先看后听”

## 11. 降级与异常处理

- 网络词典不可用：直接回退缓存或 TTS
- 语音包下载失败：标记失败，可重试
- 校验失败：删除损坏文件
- 语音包加载失败：标记 `broken`，回退系统 TTS
- 空间不足：下载前提示并阻止
- Release 资产不可达：不影响学习主流程
- 系统 TTS 未安装：提示用户启用，但不影响词典音频路径

## 12. 发版与资源策略

### 12.1 版本号

发音模块作为 `v1.2` 交付。

版本规则保持：

- `1.0 -> 1.1 -> 1.2`
- 小版本到 `1.9` 后进 `2.0`

### 12.2 资源托管

- App 主包继续通过 GitHub Actions 构建发包
- 语音包与语音包清单通过 GitHub Release 资产托管
- 正式包不直接携带大体积离线模型

### 12.3 更新日志要求

`CHANGELOG.md` 必须单列：

- 词典音频缓存
- 离线语音包下载与挂载
- 单词详情英 / 美发音
- 例句 / AI 讲解朗读
- 降级与兼容说明

## 13. 验收标准

- 单词详情页可稳定播放英式 / 美式发音
- 已播放词条再次进入时优先命中本地缓存
- 无词典音频时可自动回退离线语音包或系统 TTS
- 设置页可下载、安装、切换和删除语音包
- 长文本朗读可用，且离线语音包优先
- 发音行为能写入本地事件数据
- 升级到 `v1.2` 不丢失既有学习数据
- 继续保持 GitHub 云端发版主流程

## 14. 实施结论

`v1.2` 采用“词典音频优先 + 本地缓存 + 可下载离线 TTS 语音包 + 系统 TTS 兜底”的混合路线。

这条路线能同时满足：

- 标准单词发音质量
- 离线朗读能力
- 主包体积控制
- 无服务器条件下的长期可维护性

后续实现将围绕以下四个子模块分阶段推进：

1. 数据层与播放调度
2. 词典音频抓取与缓存
3. 语音包下载与挂载
4. 长文本朗读与 AI 数据接入
