# 文文Lex v1.1 词库扩容、Excel 导入与 AI 管理设计文档

## 1. 背景

文文Lex `1.0` 已经完成 Android 原生 MVP，具备基础学习闭环、词书管理、AI 设置、本地备份恢复和 GitHub 云端发版能力。

当前仍存在 4 个直接影响可用性的短板：

- 内置词书仍是演示规模，无法支撑真实长期学习
- “导入词书”入口已存在，但没有真正接入文件导入链路
- AI 配置仍然是单 API 单配置，不适合后续多模型和多平台切换
- 单词数据里只有单个 `phonetic` 字段，无法支持英式/美式音标、批量补全和持续回写

`v1.1` 的目标就是把这 4 个短板补齐，同时保持本地优先、无账号、无自建服务器、GitHub 云端发版的产品基线不变。

## 2. 版本目标

### 2.1 目标

- 将内置词书从演示数据升级为可持续扩容的正式书库
- 真正接入 Excel 词书导入能力
- 支持导入失败时的 AI 结构适配与内容补全
- 将 AI 配置升级为多 API 管理和快速切换
- 支持单词音标的单个补全、整书批量补全与数据库回写
- 保证 `1.0 -> 1.1` 升级过程中学习数据可保留

### 2.2 非目标

- 不引入账号系统
- 不引入云端同步
- 不新增后端服务
- 不在第一版导入中支持多 sheet 映射编辑器
- 不在第一版多 API 中实现复杂负载均衡或自动故障转移

## 3. 范围概览

`v1.1` 范围拆成 4 个模块：

1. 内置词书正式化
2. Excel 导入与 AI 适配
3. 多 API 管理与快速切换
4. AI 音标补全与落库

## 4. 内置词书设计

### 4.1 设计目标

- 内置词书必须达到真实可用规模
- 后续可以持续追加新词书，而不是每次重做结构
- 词库来源必须可追踪
- 只允许把可合法分发的数据直接打进仓库和 APK

### 4.2 词库策略

内置词书采用“双层策略”：

#### 第一层：可公开再分发的开源词表

这部分作为正式内置底库，直接放进仓库资产中。

#### 第二层：接近考试标准的公开整理版

这部分只在满足以下条件时允许并入内置资产：

- 来源可追踪
- 分发许可可核验
- 允许随项目仓库或 APK 分发

如果某个整理版只适合参考、但不允许再分发，则只允许用于内部比对和人工校正，不允许把原始内容直接打包进应用。

### 4.3 首批内置词书范围

首批建议：

- `CET4`
- `CET6`
- `考研`
- `高中`
- `雅思基础`

每本词书都必须在 `manifest` 元数据中标出来源、许可和版本信息。

### 4.4 词书资产元数据

现有 `books/manifest.json` 扩展字段：

- `sourceName`
- `sourceLicense`
- `licenseUrl`
- `sourceVersion`
- `coverage`
- `reviewedAt`

用途：

- 让后续接手者知道当前词库来自哪里
- 方便继续扩充和替换
- 在法律或来源不明确时快速排查

## 5. Excel 导入设计

### 5.1 文件格式约束

`v1.1` 只支持 `.xlsx` 文件。

默认解析规则：

- 读取第一个工作表
- 第一列为英文单词
- 第二列为中文释义
- 第二列支持英文逗号 `,` 和中文逗号 `，`

例如：

| A列 | B列 |
| --- | --- |
| abandon | 放弃，抛弃,沉溺 |

### 5.2 本地严格解析模式

导入先走本地严格解析，不先调用 AI。

本地解析要完成：

- 去空行
- 去前后空格
- 统一中英文逗号
- 合并重复释义
- 跳过无英文单词的行
- 生成导入统计结果

### 5.3 AI 适配模式

如果 Excel 不符合标准格式，或本地解析置信度过低，则进入 `AI 适配模式`。

AI 适配只允许做这些事情：

- 识别真实数据所在 sheet
- 识别英文列和中文列
- 跳过表头、注释、备注行
- 统一释义分隔符
- 补全缺失中文义
- 补全音标

AI 适配的硬限制：

- 不允许凭空生成英文单词
- A 列单词为空时，该行直接视为无效
- AI 自动补全的字段必须在导入结果中做标记
- 只有用户确认后，AI 处理结果才允许入库

### 5.4 导入结果

导入完成后：

- 生成一本文本书
- 写入导入批次记录
- 可以立即进入学习
- 可以立即发起整书音标补全

## 6. 多 API 管理设计

### 6.1 当前问题

`1.0` 只有一套 AI 配置：

- 一个 `Base URL`
- 一个 `Model`
- 一个 `API Key`

这会导致：

- 无法在多个 AI 平台之间快速切换
- 无法让不同功能使用更合适的模型
- 后续一旦加入音标补全，会与其他 AI 场景抢同一套配置

### 6.2 新设计

`v1.1` 将 AI 设置升级为“多配置列表 + 全局默认 + 功能级覆盖”。

#### 配置列表

用户可以维护多套 API 配置，每套配置包含：

- 名称
- 提供商类型
- Base URL
- Model
- 启用状态

API Key 不进入普通设置或数据库，仍通过 Android Keystore 加密保存。

#### 全局默认

用户可以指定一个 `默认 API`，默认情况下所有 AI 功能都跟随它。

#### 功能级覆盖

第一版只开放少数高价值场景做单独覆盖：

- 单词讲解
- 计划分析
- 音标补全

读取规则：

1. 先读功能级覆盖
2. 如果没有覆盖，则回退到默认 API

### 6.3 快速切换

多 API 页面必须支持：

- 快速查看当前默认 API
- 一键切换默认 API
- 编辑已有配置
- 新增配置
- 删除不再需要的配置

`v1.1` 暂不要求实现自动测速和自动故障切换。

## 7. AI 音标补全设计

### 7.1 能力目标

音标补全必须支持：

- 单个单词补全
- 整本词书批量补全
- 英式音标和美式音标优先同时存储
- 结果写回数据库

### 7.2 数据规则

音标存储规则：

- 优先存 `英式 + 美式`
- 如果 AI 只返回一套，允许先保存单套
- 原有 `phonetic` 字段继续保留作为兼容字段

需要新增以下概念字段：

- `phoneticUk`
- `phoneticUs`
- `phoneticSource`
- `phoneticStatus`
- `phoneticUpdatedAt`

### 7.3 单个补全

在单词详情页新增音标卡片和 AI 补全入口：

- `补全这一个`
- `重跑音标`

如果该词已有音标，允许重跑，但要保留来源和更新时间。

### 7.4 批量补全

用户可针对整本词书发起批量补全。

批量补全需要两种模式：

- `只补空白项`
- `确认后覆盖全部`

如果系统检测到该词书中已有音标，则先弹确认，再执行覆盖类任务。

### 7.5 数据来源标记

音标写回数据库后，必须能区分来源：

- `builtin`
- `imported`
- `ai_generated`
- `manual`
- `legacy`

这样后续才能支持人工修订、重新跑 AI、统计补全比例。

## 8. 数据模型设计

### 8.1 Word / WordEntity

在保留现有 `phonetic` 字段的前提下，新增：

- `phoneticUk`
- `phoneticUs`
- `phoneticSource`
- `phoneticStatus`
- `phoneticUpdatedAt`

语义：

- `phonetic`：兼容旧数据和兜底展示
- `phoneticUk`：英式音标
- `phoneticUs`：美式音标
- `phoneticSource`：音标来源
- `phoneticStatus`：`empty / partial / complete`
- `phoneticUpdatedAt`：最后一次更新

### 8.2 AI Provider Profile

新增 API 配置实体：

- `id`
- `name`
- `providerType`
- `baseUrl`
- `model`
- `enabled`
- `createdAt`
- `updatedAt`
- `lastValidatedAt`

用途：

- 管理多套 API 配置
- 作为全局默认和功能覆盖的引用目标

### 8.3 Import Batch

新增导入批次实体：

- `id`
- `bookId`
- `fileName`
- `sheetName`
- `parserMode`
- `totalRows`
- `importedRows`
- `skippedRows`
- `aiNormalizedCount`
- `aiCompletedCount`
- `createdAt`

用途：

- 记录导入质量
- 区分普通导入和 AI 适配导入
- 便于后续排查导入错误

### 8.4 Phonetic Enrichment Job

新增音标补全任务实体：

- `id`
- `scopeType`
- `scopeRef`
- `profileId`
- `fillMode`
- `status`
- `totalCount`
- `completedCount`
- `failedCount`
- `createdAt`
- `updatedAt`

第一版先保留任务级记录，不额外拆每个单词的明细任务表。

### 8.5 DataStore 设置项

从“保存一套 AI 配置”改为“保存配置引用关系”：

- `defaultAiProfileId`
- `wordHelpProfileId`
- `planAdjustmentProfileId`
- `phoneticFillProfileId`

说明：

- 具体 API Key 不进 DataStore
- API Key 按 `profileId` 存入加密存储

## 9. 数据库迁移设计

### 9.1 版本

- `Room version: 1 -> 2`

### 9.2 迁移内容

- 扩展 `words` 表音标相关字段
- 新建 `ai_provider_profiles`
- 新建 `import_batches`
- 新建 `phonetic_enrichment_jobs`

### 9.3 旧数据回填

如果旧版 `phonetic` 有值，而新字段为空，则：

- 先把旧 `phonetic` 回填到 `phoneticUk`
- `phoneticStatus = partial`
- `phoneticSource = legacy`

这样 `1.0` 用户升级到 `1.1` 后不会丢失已有音标展示。

### 9.4 兼容目标

- `1.0 -> 1.1` 升级后学习数据保留
- 旧版备份恢复到 `1.1` 时允许只带单音标
- 新版备份回退到旧版不保证兼容，但需要在文档中明确说明

## 11. 错误处理

### 11.1 Excel 导入

- 文件无法读取：提示格式不支持或文件损坏
- 工作表为空：提示未找到有效数据
- 有效行过少：提示确认是否启用 AI 适配
- AI 适配失败：保留本地已识别数据，不清空已有结果

### 11.2 多 API

- 配置缺少 `Base URL` 或 `Model`：禁止保存
- API Key 缺失：允许保存配置草稿，但不能设为可用
- 覆盖引用的配置被删除：自动回退到默认 API

### 11.3 音标补全

- 当前功能未分配可用 API：提示先配置或切换 API
- AI 返回空结果：记录失败次数，不覆盖原值
- 批量任务中断：保留已完成结果，允许稍后重新发起

## 14. 风险与约束

### 14.1 词库来源风险

最大风险是“接近考试标准的公开整理版”可能存在再分发限制。

控制方式：

- 具体词库源必须在实现前逐个核验许可
- 只有可合法分发的数据允许进入仓库和 APK

### 14.2 Excel 复杂格式风险

用户实际 Excel 可能包含：

- 多 sheet
- 合并单元格
- 表头不在第一行
- 备注列、序号列

控制方式：

- 先做严格格式约束
- 不满足时引导进入 AI 适配模式
- 第一版不做复杂可视化列映射器

### 14.3 AI 结果不稳定风险

AI 可能返回：

- 单套音标
- 低质量中文义
- 无法稳定识别列

控制方式：

- AI 只作为增强层，不是唯一入口
- 所有 AI 自动补全项都要可标记、可重跑、可覆盖

## 15. 验收标准

`v1.1` 视为达标，至少需要满足：

- 内置词书不再是 3 词演示数据
- 用户可以导入符合格式的 `.xlsx` 词书
- 格式不规整时可以进入 AI 适配并完成可确认导入
- 用户可以维护多套 API 配置并快速切换
- 用户可以单个或整书补全音标
- 音标补全结果会写回数据库
- `1.0 -> 1.1` 升级后学习数据保留
