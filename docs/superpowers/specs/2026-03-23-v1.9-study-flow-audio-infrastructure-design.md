# 文文Lex v1.9 学习流与发音基础设施设计

日期：2026-03-23  
状态：已完成用户确认，待进入实施计划  
范围：学习任务分流、分组学习流程、单词过关标准、复习节奏、发音来源与缓存治理、语音包下载治理

## 1. 背景

当前文文Lex 的学习体验还没有形成产品级闭环。

现状问题：

- 首页会展示“新词 / 复习 / 错词”任务，但学习页实际仍直接加载整本词书，首页计划没有真正驱动队列。
- “开始新词学习 / 开始复习 / 最近错词”三个按钮没有分流成三种学习模式，而是都跳到同一条学习路径。
- 每日目标的语义不清，目前更像“展示文案”，而不是“今日新词引入量”。
- 发音链路虽然已有词典缓存、在线词典、本地离线与系统 TTS 的部分实现，但来源不可解释、缓存不可管理、语音包下载恢复能力不足、云端 TTS 入口缺失。

用户当前的核心要求有两条：

1. 学习体验必须先把最基本的产品体验做好，不能继续是“整本书直接刷到底”。
2. 之前长期暴露的语音包、缓存、来源切换、下载失败、取消下载、云端 TTS 接口等问题，要和学习流一起收口。

## 2. 竞品结论：不背单词的“背词形式”

本设计不复制不背单词的全部实现细节，但吸收其公开可见且对文文Lex 有价值的形式特征。

基于官方 App Store 页面、公开报道、公开经验总结与论文分析，可以得到以下结论：

- 不背单词不是“整本词书一路刷完”，而是按任务模式组织学习，至少可见 `Learn`、`Review`、`备考速刷` 等入口。
- 它按组推进学习和复习，且学习组大小与复习组大小可分别设置。
- 它强调“语境中的单词”，单词卡不是只有词和中文义，还包含发音、例句、搭配、词根词缀、派生与相关词。
- 它把“拼写”作为重要的过关步骤之一，且新版本已支持“学习后是否拼写 / 复习后是否拼写”分别配置。
- 它的学习目标不是“看过”，而是“通过多轮回忆后进入复习阶段”；复习再由间隔算法持续拉回。

本设计对不背单词的吸收原则：

- 吸收“任务分流、分组推进、过关式学习、拼写可选、复习独立于新词”的产品结构。
- 不在第一版直接复制其完整多轮重考试流，而是先实现稳定、可理解、可迭代的轻量版本。

## 3. 设计目标

### 3.1 目标

- 明确 `每日 20 词` 的含义：只表示“今天引入 20 个新词”。
- 把首页三个入口真正分成三条学习队列：新词、复习、最近错词。
- 学习页从“整本词书直刷”改为“按组推进”。
- 为单词定义清晰的本轮过关标准与长期复习状态。
- 让发音系统成为可解释、可切换、可缓存、可批量生成、可恢复的基础设施。
- 统一处理词典缓存、云端 TTS 缓存、本地语音包生成缓存。

### 3.2 非目标

- 不在 v1.9 里做完整考试系统或复杂题型矩阵。
- 不在 v1.9 里完全复制不背单词的所有细节动画、商业化逻辑或全部学习模式。
- 不在 v1.9 里做公开可分发的词典音频包发布；词典音频仅做本机预缓存与本机备份使用。

## 4. 核心定义

### 4.1 每日目标

`每日 N 词` 定义为：当天允许首次引入的新词数量上限。

它不包含：

- 到期复习词
- 最近错词回拉
- 已学词的强化回看

这三类任务单独展示、单独进入、单独统计。

### 4.2 三类首页任务

首页只保留三类主学习入口：

- `开始新词学习`
  - 仅取当前词书中未学的新词。
- `开始复习`
  - 仅取 `nextReviewAt <= now` 的到期复习词。
- `最近错词`
  - 仅取最近 3 天内出现“错误 / 模糊”结果的词。

这三类入口必须生成三条不同队列，不能再共用“整本词书学习页”。

### 4.3 词的“合格”定义

分两层：

- `本轮合格`
  - 本次学习任务里，这个词完成了规定步骤并通过。
- `长期合格`
  - 词已经进入长期复习阶段，并在多次复习中保持较高稳定度。

v1.9 只实现清晰的本轮合格与复习回退，不在首版引入复杂稳定度公式。

## 5. 学习流程设计

### 5.1 分组推进

每次学习不再以“整本词书”为单位，而是以“组”为单位。

默认组大小：

- 新词：5 词/组
- 复习：20 词/组
- 最近错词：10 词/组

后续可配置，但 v1.9 先提供稳定默认值，避免用户第一次进入就被设置项淹没。

### 5.2 单词学习步骤

单词在本轮学习中的标准流程：

1. `识义`
   - 看到单词、音标、基础义项与例句。
   - 用户通过“认识 / 模糊 / 不认识”给出主观反馈，必要时可加简易义项确认。
2. `回想`
   - 提供中文义或例句线索，要求用户回想英文词。
3. `拼写`
   - 默认可配置。
   - 开启时，拼写通过才算本轮真正过关。

### 5.3 一组结束后的收口页

每组结束后必须有收口页，而不是无缝滑入下一组。

收口页至少展示：

- 本组词数
- 已通过词数
- 待回拉词数
- 是否进入拼写
- 下一组入口

这是把“完成任务”感明确传达给用户的关键体验点。

## 6. 单词状态与复习模型

### 6.1 状态机

单词状态采用有限状态机：

- `UNSEEN` 未学
- `LEARNING` 学习中
- `LEARNED_PENDING_REVIEW` 初学通过，等待首次复习
- `REVIEW_DUE` 到期复习
- `FAMILIAR` 多轮复习通过，进入稳定阶段
- `RELAPSED` 回退状态

状态切换原则：

- 初学流程全部通过：进入 `LEARNED_PENDING_REVIEW`
- 到达复习时间：进入 `REVIEW_DUE`
- 连续复习通过多次：进入 `FAMILIAR`
- 模糊或错误：回退到更早阶段，并写入“最近错词”

### 6.2 v1.9 复习节奏

首版采用稳定固定间隔，先追求可解释与稳定：

- 初学通过：10 分钟后
- 复习通过第 1 次：1 天后
- 第 2 次：3 天后
- 第 3 次：7 天后
- 第 4 次：15 天后
- 第 5 次：30 天后

回退规则：

- `模糊`：退 1 档
- `错误 / 不认识`：退 2 档，并加入最近错词

说明：

- 这不是对不背单词内部算法的复刻，而是针对文文Lex 首版稳定性的工程化折中。
- 后续可再叠加 AI 动态调整，但 v1.9 先用可验证的固定间隔闭环。

## 7. 首页任务与学习队列的真实闭环

### 7.1 首页只显示真实可执行任务

首页各项统计必须基于真实学习记录和当前词书计算，而不是纯展示层推导。

需要展示：

- 今日新词目标
- 今日剩余新词
- 今日到期复习
- 最近错词
- 当前词书
- 预计时长

### 7.2 学习入口必须携带模式参数

导航层新增学习模式参数，例如：

- `study?mode=new_words`
- `study?mode=review`
- `study?mode=recent_mistakes`

学习页在加载时按模式构造队列，而不是再默认取整本词书。

### 7.3 空任务状态

如果当前模式下没有可学习词，必须显示明确空状态，而不是回退到整本词书：

- 新词为空：提示“今天的新词已完成”
- 复习为空：提示“当前没有到期复习词”
- 最近错词为空：提示“最近没有需要回拉的错词”

## 8. 发音系统设计

### 8.1 设计原则

发音不是附属按钮，而是学习流中的基础设施。

系统必须满足：

- 当前来源可解释
- 来源可切换
- 缓存可管理
- 后台任务可观测
- 下载失败可恢复

### 8.2 默认发音优先级

v1.9 默认采用“词典优先”策略：

1. 词典缓存
2. 在线词典
3. 云端 TTS 缓存
4. 实时云端 TTS
5. 本地语音包缓存 / 本地预生成
6. 系统 TTS

用户可切换默认来源策略，但首版推荐词典优先。

### 8.3 学习页 / 详情页来源详情

点击“播放发音”后，界面必须能说明：

- 当前实际命中的来源
- 当前口音
- 是否已缓存
- 文件大小
- 下次是否可离线播放

并提供快速切换：

- 词典缓存 / 在线词典
- 云端 TTS
- 本地语音包
- 系统 TTS

### 8.4 三类独立缓存

统一音频缓存体系，但按来源分桶：

- `dictionary_cache`
  - 在线词典音频缓存
- `cloud_tts_cache`
  - 云端 TTS 生成缓存
- `local_voice_pack_cache`
  - 本地语音包批量生成缓存

三类缓存都必须可统计、可清理、可查看明细。

## 9. 后台批量缓存任务

### 9.1 独立任务类型

批量缓存不采用混合任务，而是三类独立任务：

- 在线词典预缓存
- 云端 TTS 预生成
- 本地语音包预生成

这样做的原因：

- 来源清晰
- 失败原因清晰
- 便于分别暂停 / 取消 / 清理
- 便于后续做来源质量对比

### 9.2 任务范围

三类任务共享相同的范围选择器：

- 当前词书
- 指定词书
- 指定单元
- 选中的若干单词
- 智能范围
  - 最近学习词
  - 最近错词
  - 高频词

### 9.3 任务能力

每个后台任务需要支持：

- 创建
- 运行中进度显示
- 暂停
- 继续
- 取消
- 查看失败原因
- 完成后进入缓存明细

## 10. 缓存管理页

### 10.1 统一入口

缓存管理页作为单独页面，不再只在设置页展示一张“总大小 + 清空缓存”卡片。

### 10.2 能力

必须支持：

- 查看总缓存大小
- 按来源分桶查看
- 调整总上限
- 自动淘汰策略
- 按词书 / 单词 / 来源筛选
- 清空某一来源
- 清空全部缓存

### 10.3 上限与淘汰

缓存上限允许 50 MB - 2048 MB。

淘汰策略：

- 默认按最近最少使用（LRU）自动淘汰
- 优先淘汰体积大且长期未播放的缓存
- 默认不主动淘汰最近 7 天刚生成的缓存，除非空间压力极高

## 11. 语音包下载治理

### 11.1 目标

修复用户当前最痛的语音包体验问题：

- 下载失败但原因不明
- 无法取消
- 无法恢复
- 不知道是源站问题还是本地问题

### 11.2 能力要求

语音包下载必须支持：

- 下载中取消
- 断点续传
- 下载失败原因展示
- 重试
- 全量重下
- 切换下载源

### 11.3 失败原因分类

至少区分：

- 源站超时
- 网络中断
- 不支持 Range
- 校验失败
- 解压失败
- manifest 缺失或不合法

## 12. 云端 TTS 接入口

### 12.1 v1.9 范围

云端 TTS 在 v1.9 正式接入：

- Provider 配置入口
- API 检测按钮
- 试听按钮
- 设为默认云端来源
- 实时云端播放
- 云端批量预生成缓存

### 12.2 多 Provider 扩展位

首版可先以小米 MiMo TTS 为第一个 Provider，但架构需要预留：

- 多 Provider 配置
- 快速切换默认 Provider
- Provider 级能力检测
- Provider 级缓存来源标识

## 13. 数据模型调整方向

v1.9 需要补齐以下模型能力：

### 13.1 学习记录

在现有 `LearningRecord` 基础上扩展：

- `learningStage`
- `reviewStage`
- `introducedAt`
- `lastMistakeAt`
- `lastFuzzyAt`
- `lastStudyMode`
- `currentGroupPassState`

### 13.2 学习会话

补充会话级模式与范围：

- `mode`
- `scopeType`
- `scopeRef`
- `groupSize`
- `currentGroupIndex`

### 13.3 音频任务

新增后台任务实体：

- `audio_generation_jobs`

字段建议包括：

- `jobType`
- `sourceType`
- `scopeType`
- `scopeRef`
- `status`
- `totalCount`
- `completedCount`
- `failedCount`
- `lastError`
- `createdAt`
- `updatedAt`

## 14. 错误处理与基础体验要求

### 14.1 基础体验底线

以下问题属于 v1.9 必修项：

- 学习页不能再出现“空白卡片先出现，再慢慢补内容”的不稳定状态。
- 首页按钮语义与实际行为必须一致。
- 空任务时不能偷偷回退为“整本词书学习”。
- 发音来源不能再只用一句模糊状态文案带过。
- 语音包失败时用户必须知道为什么失败、接下来能做什么。

### 14.2 典型错误文案

界面必须能明确区分：

- `已联网获取词典音频，已缓存，下次可离线播放`
- `当前播放：云端 TTS 缓存`
- `当前播放：本地语音包生成缓存`
- `语音包下载失败：源站超时，可继续下载或切换镜像`

## 15. 测试与验收

### 15.1 学习流验收

- 首页三个入口进入三种不同队列
- 每日新词目标不会再把整本词书误当成今日任务
- 新词 / 复习 / 错词各自按组推进
- 一组结束后有收口页
- 单词过关会更新学习记录与下次复习时间

### 15.2 发音验收

- 学习页与详情页都能显示实际命中的发音来源
- 三类后台缓存任务都能创建、暂停、继续、取消
- 缓存管理页能按来源查看与清理
- 语音包下载支持取消与续传
- 云端 TTS 可检测、试听、实时播放、批量生成缓存

## 16. 分阶段实施建议

建议拆成三个实施波次：

### Wave 1：学习流闭环

- 首页任务分流
- 学习模式参数化
- 分组推进
- 本轮过关链路
- 收口页
- 基础学习记录扩展

### Wave 2：发音可解释与缓存治理

- 发音来源详情
- 统一缓存管理页
- 缓存上限调节与自动淘汰
- 三类后台缓存任务框架

### Wave 3：语音包与云端 TTS 收口

- 语音包下载取消 / 续传 / 失败恢复
- 云端 TTS Provider 接入
- 实时云端播放与缓存
- 多 Provider 扩展位
